# Forgectl Repository Guidance

## Part of the cadence stack

forgectl is the workbench control plane of the cadence methodology stack: the binary that starts Claude Code sessions with a project's posture, opens them in terminal surfaces, runs blessed workflows, and edits env files without a secret value ever reaching argv or a transcript.

Agents drive it under the agent contract in [ADR-0008](docs/adr/0008-agent-contract.md): no TTY interaction without a TTY, `--json` on anything that prints state, honest exit codes, printable effective configuration. Per-command reference lives in [`docs/commands/`](docs/commands/).

Two facts an agent working in a cadence-equipped session should know:

- In a cadence-equipped session, the secret guards block direct edits and shell reads of `.env`-shaped files; `forgectl env` is the invocation form they accept. `forgectl env set KEY` reads the value from stdin or the clipboard, never argv.
- Friction met from a Claude Code session can be filed with `/cadence:feedback`. Humans file here directly.

## Release notes

`CHANGELOG.md` is generated by Release Please. Do not edit it in feature or fix
branches, and do not add an `[Unreleased]` section.

For a consumer-visible change that needs richer prose than the squash title,
put one or more valid Conventional Commit lines in the pull-request body before
merge:

```text
BEGIN_COMMIT_OVERRIDE
fix(scope): describe the consumer-visible change
END_COMMIT_OVERRIDE
```

Release Please reads that block from the merged squash PR and generates the
versioned changelog entry. Use at most one override block per PR. Changes with no
consumer effect need no release-note override.

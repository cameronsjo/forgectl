# Forgectl Repository Guidance

## Release notes

`CHANGELOG.md` is generated by Release Please. Do not edit it in feature or fix
branches, and do not add an `[Unreleased]` section.

For a consumer-visible change that needs richer prose than the squash title,
put one or more valid Conventional Commit lines in the pull-request body before
merge:

```text
BEGIN_COMMIT_OVERRIDE
fix(scope): describe the consumer-visible change
END_COMMIT_OVERRIDE
```

Release Please reads that block from the merged squash PR and generates the
versioned changelog entry. Use at most one override block per PR. Changes with no
consumer effect need no release-note override.
